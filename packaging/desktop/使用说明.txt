DIP 3.0 医保分组器 · 桌面客户端（绿色版）
================================================================

一、怎么用
----------------------------------------------------------------
1. 把整个文件夹解压到任意位置（例如 D:\DIP3桌面版）。
   ⚠ 必须整体解压后使用，不要只把 exe 单独拷走 —— exe 需要同目录下的
     config\ 与 data\ 才能工作。

2. 双击「启动 DIP3 桌面版.bat」即可打开程序。
   也可以直接双击 Dip3Grouper.Desktop.exe。

3. 需要「基层病种兜底」时（与院内正式服务口径一致），
   请双击「启动 DIP3 桌面版 - 基层兜底.bat」。

4. 本程序免安装、不写注册表、不占端口，也不依赖 Node.js 与 .NET 运行时
   （运行时已打包在本文件夹内）。拷到别的电脑直接能用。

二、界面结构
----------------------------------------------------------------
前台（主窗口，顶部页签）
  · 单条分组 —— 输入主/其他诊断、主/其他手术，支持编码或中文拼音联想，
                可选「启用医保编码映射」，出结果卡与映射链
  · 批量分组 —— 上传 Excel / 粘贴表格 / 下载模板，导出带分组结果的工作簿
  · 病种库查询 —— 浏览全部区段，任意字段 + 拼音检索
  · 立项指南查询 —— 价格项目（含类别使用说明、计价说明）与解读辅导
  · 德州物价查询 —— 规范整合后执行的新项目（三级价格 / 医保支付 / 常用收藏）；
                顶部分段切到「作废对照」可查各批次公布作废的原价格项目；
                切到「旧版物价」可查规范整合前的 45 号文旧价格表——已作废的行
                自动标红并给出对应的现行标准（新项目编码与名称），可只看已作废或现行
                及其对应的新项目（无替代的标「直接废止」），
                支持按批次、类别与新旧编码 / 名称互查（含拼音）

后台（点主窗口右上角的「后台管理」按钮）
  · 概览 —— 病种库 / 映射表 / 综合病组 / 立项指南 的规模与导入来源
  · 病种库管理 —— 区段增删改、整库导入、区段导入、模板导出
  · 立项指南 —— 价格项目增删改、区段导入、模板、类别使用说明、解读辅导导入
  · 映射与灰码 —— ICD-10 → 医保编码映射表（灰码标记可勾选）
  · 综合病组 —— 追加兜底层增删改、Excel 导入、模板、清空
    （病种库内置综合病组 = 结核区间行 26 条，随病种库维护，不在此页）

三、数据放在哪
----------------------------------------------------------------
  config\dip3-config.json   病种库配置（14,000+ 条）
  data\mappings.json        ICD-10 → 医保编码映射表
  data\lixiang.json         立项指南（区段 + 解读辅导）
  data\zonghe.json          综合病组
  data\config-meta.json     病种库导入元信息

这些都是纯文本 JSON。直接替换文件即可更新数据；后台里的导入功能会
自动写回同名文件（导入病种库前会先备份成
config\dip3-config-<时间戳>.bak.json）。

如果想把数据放到别处（比如共享盘），设置环境变量 DIP3_HOME 指向那个
目录即可（该目录下要有 config\ 与 data\）。

四、自检（排障用）
----------------------------------------------------------------
在命令行里执行：

    Dip3Grouper.Desktop.exe --selftest

程序会不打开窗口，跑一遍数据链路 + 全部页面构造，把结果写到

    %TEMP%\dip3-desktop-selftest.log

全部通过时退出码为 0。若程序启动异常、页面空白，先跑这个看日志。

五、命令行参数
----------------------------------------------------------------
  --jiceng          开启基层病种兜底
  --home <目录>     指定数据根目录（含 config\ 与 data\）
  --selftest        自检模式（不打开窗口）

六、常见问题
----------------------------------------------------------------
Q: 双击后一闪而过？
A: 多半是没有整体解压，或 config\ / data\ 缺失。用命令行运行看报错信息，
   或先设 DIP3_HOME 指向数据目录。

Q: 提示「启动失败」？
A: 程序找不到 data\ 与 config\。确认这两个子目录在 exe 旁边。

Q: 分组结果和院内系统不一致？
A: 先确认基层兜底开关是否一致（正式服务开启 --jiceng）；再确认
   data\mappings.json 与 config\dip3-config.json 是否是同一版本。

Q: 点右上角 ✕ 为什么会弹「关闭程序」确认框？
A: 问你「最小化到托盘」（默认按钮，程序留在后台继续收通知公告）还是
   「退出程序」。勾上「记住我的选择」以后就不再问；想改回来去
   「后台管理 → 系统设置 → 窗口与托盘」。系统关机 / 注销时不弹这个框，
   会直接退出，不会挡住关机。

Q: 想同时用网页版？
A: 本绿色版不含网页版。网页版请用仓库的 run-web.bat 启动。

七、从服务端更新数据（含"跟随服务端设置"）
----------------------------------------------------------------
服务端发的通知公告，本程序也收得到：主窗口右上角有个铃铛，
有新通知时显示红色数字，钉住的通知会常驻在导航栏下方的横幅里；
发现新消息时还会弹一次系统托盘气泡。点铃铛看全部消息。
（前提：本机已在「后台管理 → 数据更新」里填了服务器地址。）

如果服务端设置了「数据分发共享口令」（服务端后台 → 系统设置 →
数据分发共享口令），把同一个口令填到数据源配置的「共享口令」里。

如果院里有一台机器跑「数据服务端」，本机就不用手工换数据文件：

  主窗口 →「后台管理」→ 左侧「数据更新」
    · 服务器地址填  http://<服务端IP>:3210
    · 若服务端设了共享口令，把口令一并填上
    · 点「检查更新」→ 有差异就点「立即更新」

更新过程会自动备份被覆盖的文件，可在「备份与回滚」卡片里整体还原。
连不上服务器不影响使用：本机会照常用已有数据。

同一张卡片上还有「跟随服务端公共设置」（默认开）与「立即同步设置」：
勾上后，服务端后台改的 软件名称 / 单位副名 / 立项指南参数 会自动
下发到本机（启动时同步一次、更新数据后也会同步），窗口标题与
新增立项项目时的下拉候选跟着变。

  不会下发的：后台登录口令、界面主题、关闭行为（先询问 / 收托盘）、
              服务器地址、德州物价的常用收藏 —— 始终归本机自己管。
  服务端某项留空 = 那边没配，本机保持原样，不会被清空。

想在某台机器上单独用别的软件名，就在「后台管理 → 系统设置」里
关掉跟随（页面顶部会写明本机正在跟随服务端）。

八、升级客户端时，本机设置不会丢
----------------------------------------------------------------
把新版程序文件夹盖到原目录（或重新解压一份到原目录）时，下面这些
"用起来才有"的文件会原样保留：

  data\settings.json         软件名称 / 副名 / 后台口令 / 数据源配置
  data\dezhou-favorites.json  德州物价的常用收藏
  data\_backup\              历次更新的备份点

注意：升级前请先退出程序（程序在跑会占用文件，导致升级失败）。
