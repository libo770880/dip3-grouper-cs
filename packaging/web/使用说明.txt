DIP 3.0 医保分组器 · 数据服务端（绿色版）
================================================================

一、这台机器是什么角色
----------------------------------------------------------------
这是「数据主库」机器。全院的其他电脑（装了桌面客户端）都从这里
拉取最新的病种库、映射表、立项指南、德州物价等数据。

服务端同时也是一个完整的网页版分组器：
浏览器打开 http://localhost:3210 就能直接用，不装客户端也行。

二、运行环境（先看这一段，能省掉很多来回）
----------------------------------------------------------------
· 不用装 .NET，不用装数据库，不用装 Office，也不用装 VC++ 运行库。
  运行时（约 190MB）已经随绿色包一起发，双击就能跑。
· 支持 Windows 10（1809 及以上）/ Windows 11；32 位系统请用
  DIP3-Web-win-x86 那个包（64 位系统用哪个都行）。
· 「其他电脑」指科室里要打开网页的电脑：它们什么都不用装，
  用 Edge / Chrome 打开服务端给出的局域网地址即可。
  换句话说 —— 整个科室只有这一台机器需要解压这个包。
· 首次启动时 Windows 可能弹「是否允许此应用通过防火墙」，必须点【允许】，
  否则其他电脑打不开。点错了也不要紧，按第三节手工放行一次即可。

三、怎么启动
----------------------------------------------------------------
1. 把整个文件夹解压到任意位置（例如 D:\DIP3服务端）。
   ⚠ 必须整体解压后使用，不要只把 exe 单独拷走 —— exe 需要同目录下的
     config\、data\、web\ 才能工作。

2. 双击 Dip3Grouper.WebShell.exe 启动（绿色版主入口，不用开命令行）。
   启动后：
     · 没有黑色命令行窗口，而是一个小面板，上面写着「服务运行中」；
     · 面板自动列出四条信息（不用自己查 IP）：
           本机访问   http://localhost:3210
           局域网访问 http://192.168.x.x:3210   ← 其他电脑填这条
           后台管理   http://192.168.x.x:3210/admin
           数据目录   data 文件夹的实际位置
       每条右侧都有「打开 / 复制」，局域网那条复制下来直接发给同事即可；
     · 局域网地址是按当前网卡自动挑的：有多块网卡（Wi-Fi + 网线、
       或装了 VMware/VirtualBox 的虚拟网卡）时，会优先选真正连着
       路由器的那一块，不会把 192.168.x.1 这类虚拟地址发出去；
       插拔网线、切换 Wi-Fi 之后点一下面板上的「刷新地址」即可；
     · 浏览器会自动打开分组器页面，可以直接开始用。

3. 面板右上角的 × 只是把它收进右下角系统托盘，服务继续运行；
   要真正停止服务，点面板上的「退出服务」，或托盘图标右键 →「退出（停止服务）」。
   托盘图标双击可以重新打开面板。

4. 换端口：在本文件夹打开命令行执行
       Dip3Grouper.WebShell.exe --port 3220
   面板里的地址会自动跟着变。（也可以双击 bat 并带参数：启动 DIP3 数据服务端.bat 3220）

5. 需要做成 Windows 服务、或想在控制台看日志时，用同目录的命令行版：
       Dip3Grouper.Web.exe --port 3210

四、让局域网内其他电脑能连上（重要）
----------------------------------------------------------------
Windows 防火墙默认会拦住 3210 端口，请在【这台机器】上放行一次：

  控制面板 → Windows Defender 防火墙 → 高级设置
    → 入站规则 → 新建规则 → 端口 → TCP → 特定本地端口填 3210
    → 允许连接 → 全部勾选（域/专用/公用）→ 名称填 DIP3 数据服务

放行后，在另一台电脑上先用浏览器访问 http://<服务端IP>:3210 试一下，
能打开分组器界面就说明网络通了。地址直接抄服务端面板上「局域网访问」那一条，
不要手打 —— 尤其是机器有多块网卡时，肉眼猜 IP 很容易猜错。

五、客户端怎么连
----------------------------------------------------------------
在客户端：主窗口 →「后台管理」→ 左侧「数据更新」
  · 服务器地址填  http://<服务端IP>:3210
  · 若服务端设了共享口令，把口令一并填上
  · 点「检查更新」→ 有差异就点「立即更新」

更新过程会自动备份被覆盖的文件到 data\_backup\<时间戳>\，
在「备份与回滚」卡片里可以随时整体还原。

同一张卡片上还有一个开关「跟随服务端公共设置」（默认开）：
勾上后，本服务端后台里改的 软件名称 / 单位副名 / 立项指南参数
会自动下发到这台客户端（启动时同步一次，更新数据后也会同步），
不用每台机器手工改一遍。

  不会下发的：后台登录口令、界面主题、「关闭到最小化托盘」、
              服务器地址、德州物价的常用收藏 —— 这些始终归本机自己管。

连不上服务器不影响使用：客户端会照常用本机已有数据。

六、离线机器怎么办
----------------------------------------------------------------
服务端：「数据更新」页 →「导出更新包…」得到一个 zip
离线机：「数据更新」页 →「导入更新包…」选择该 zip
效果与在线更新完全一致。

七、数据放在哪
----------------------------------------------------------------
  config\dip3-config.json   病种库配置
  data\mappings.json        ICD-10 → 医保编码映射表
  data\lixiang.json         立项指南（区段 + 解读辅导）
  data\dezhou-price.json    德州市物价
  data\guifan.json          全国医疗服务项目技术规范
  data\zonghe.json          综合病组兜底层
  data\notice.json          消息推送内容（后台发布、前台读取）
  data\settings.json        软件名 / 主题 / 后台账号口令 / 数据源配置
  data\_backup\             每次更新前的自动备份

⚠ data\settings.json 与 data\dezhou-favorites.json 是「本机私有」文件，
  永远不会被下发给客户端（客户端各自的主题、口令、常用收藏互相独立）。

八、网页后台的登录（改数据的操作需要）
----------------------------------------------------------------
http://<服务端IP>:3210/admin 是网页后台。规则很简单：

  · 「看」不用登录 —— 概览、病种库、映射表、立项指南、德州物价、
    模板下载、导出，谁打开都能用；
  · 「改」才要登录 —— 导入、新增、修改、删除、灰码标注。

没登录时点这些操作，页面会自己弹出登录框。默认账号 admin / admin123。

⚠ 请务必第一次就改掉默认口令：
  后台 → 系统设置 → 后台登录 → 填新密码 → 保存。
  口令与桌面客户端共用同一份（data\settings.json），改一处两端一致。

忘了口令：停掉服务，用记事本打开 data\settings.json，把
  "adminPass": "pbkdf2$..."  这一行改成
  "adminPass": ""
保存后重启服务，口令即恢复为 admin123。

连续输错 5 次口令会锁定 60 秒（该机器），之后自动解锁。
确实不需要登录时，可在「系统设置 → 后台登录」里关掉开关，但那样
局域网内任何人都能改数据，只建议在完全可信的内网里临时使用。

九、网页上还能改什么
----------------------------------------------------------------
后台 → 系统设置，共三项（都是网页端有意义的）：

  · 基本设置    软件名称、单位/副名（网页标题与侧栏品牌跟随）
  · 后台登录    登录开关、账号、口令
  · 立项指南参数 项目类别 / 计价单位的下拉候选（留空=自动取现有值）
  · 数据分发共享口令 保护「给客户端更新数据」的接口（/api/data/*）。
    留空 = 不校验；填了之后，客户端必须在「后台管理 → 数据更新」里
    填同一个口令才拉得到数据。它与上面的后台登录口令是两回事；
    通知公告和软件名称不受它影响（全院本来就要免登录可见）。

没配过参数表时，这两个框里会自动显示"现有数据里出现过的类别/单位"
（不是空的），可直接在此基础上增删后点「保存」；点「从现有数据提取」
也能一键灌进去。全部清空再保存 = 恢复成"自动取现有值"。

界面主题、「关闭时最小化到托盘」属于桌面客户端，网页端不提供。

十、给全院发通知（消息推送；浏览器前台和桌面客户端都收得到）
----------------------------------------------------------------
后台 →「消息推送」页，写完点「保存」，前台（就是大家打开的分组页面）
右上角会多出一个「🔔 消息」按钮，60 秒内自动收到，不用让他们刷新页面。

  · 级别    一般（蓝）/ 提醒（橙）/ 重要（红），只是配色和图标不同
  · 钉住    勾上 = 常驻显示在页面顶部导航条下面（适合"长期须知"）
            不勾 = 只进「消息中心」抽屉；有未读时会自动弹开一次
  · 生效期  留空 = 立即生效、一直有效
            填了 = 只在时间段内出现，到点自动出现、过期自动消失
            （适合"10月8日起执行新病种库"这类通知，提前写好不用守着点发布）
  · 发布    不勾「立即发布」就是草稿，只有登录后台的人能看到，前台看不见

前台同事点消息右上角的 ✕ 只是让"他那台电脑"不再显示，不会删掉通知，
也不影响别人 —— 不用怕被谁点没了。
写错了/不需要了：后台列表里点「删除」，前台立刻消失。

十一、重新发布/升级服务端时，设置不会丢
----------------------------------------------------------------
把新版程序文件夹盖到现有部署上（或重新解压一份到原目录）时，
下面这些"跑起来才有"的文件会原样保留，不用重新配：

  data\settings.json        软件名称 / 副名 / 后台口令 / 数据源配置
  data\notice.json          已发布的通知公告
  data\dezhou-favorites.json 德州物价的常用收藏
  data\_backup\             历次更新的备份点

注意：发布/升级前请先把服务窗口关掉（程序还在跑会占用文件导致升级失败）。
数据本身（病种库、映射表、立项指南、物价、技术规范）会跟着新版一起更新，
这是正常的 —— 它们本来就是靠发布来更新的。
